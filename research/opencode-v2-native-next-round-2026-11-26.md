## Changes verified

- **30**, `c3727bafcb4a2be81f0dcf0701b551c1ad08763f` and `bad91207da8b13fce9d113d8703ea8d71ad62291`. One host can load the plugin for several locations. Each live bridge has its own authenticated route for a target, generation and boot. The node binds a transport to that instance, verifies the calling native session and retires individual instances on unload. Revoking a generation retires its whole set. If two live instances prove the same native session in the same directory, both lose authority for that session until the overlap ends. Independent sessions remain usable. A fresh request can reestablish the surviving instance's original binding. A target-only bootstrap call with an authenticated configuration can return limited node status. The previously installed plugin retains its single-instance route. A current plugin is installed through the owner's setup transaction.
- **31**, `d5379793e1b797c887bf371b53238a61df994e84`. Registration records the actual v2 host version. Startup checks the native session, RPC, event and MCP interfaces and waits for the event subscription barrier. Receipt requires both the returned inbox item and the committed delivery event. The decoder accepts the two observed session metadata keys and the two inbox timestamp formats. Configuration status, runtime registration, unsupported interfaces and a stopped node have distinct UI states in all 15 locales.
- **32**, `8fbfc26b5a56ec1d99708b267ffcf121891b24bf`. Startup offers the matching setup path for an installation with verified major 1 or 2. Unversioned installations expose both labeled choices. Existing v1 configuration remains visible, and setup writes require the owner's selected action and applicable replacement confirmation.

## Stopped node and scope of the evidence

The Debian-HSA user's NCF 1.0.0 run used OpenCode CLI 2.3.2, a modified adapter pin, a local mock and direct tools. Terminating the manually started NodeService preceded the reported `V2_BRIDGE_UNAVAILABLE`. Starting it and installing the complete plugin allowed registration. The user reported two explicitly transferred agents retaining history and a successful wake, text and attachment exchange. Their attachment digest was `6b5cb2677ba4314de3be16f49cb718ba22062ced5388a6823c65bf53e0f6d12c`. Their v2 tests reported 95 passes and one skip, the project suite reported 923 passes and 26 skips, and npm audit reported zero findings.

The separate one-location NodeService test in `d0e155eb62c6dd6ab401973be2f4e527368ad870` observes `V2_REGISTRATION_UNAVAILABLE` when the node is stopped, followed by successful registration using the same provision after Start. The native direct-mode cases also verified the stopped endpoint was unreachable. A service manager with automatic restart remains an operational proposal. Current service startup and Stop behavior are preserved.

Source fixtures cover individual-location unload while a sibling remains usable, conflicting context, older plugin admission, revocation, the timestamp/metadata and event-filter boundaries, and an uncertain post-invocation outcome without repeat submission. Native single-location unload and deliberately interrupted receipt were not exercised. Four real CLI releases were tested. The remaining released v2 tags, future tags, OpenCode Desktop, Windows, and the reporter's Ubuntu/Debian environments do not have native acceptance results from this run. The Electron smoke exercises the NCF desktop interface.

## Verification

The final OpenCode v2 group passed 114 tests with one Windows-specific skip. The startup, discovery and application setup group passed 79 tests with one skip. Type checking, formatting, the application build and the isolated NCF Electron UI smoke passed. The eight native outcomes, including the two attachment digests for each run, are also retained in the local bench under `evidence/2026-11-26-native-matrix.json`.

An initial whole-project test invocation stopped making progress in the Claude Code helper file and was terminated. That file passed all 12 tests on a longer bounded retry. A later whole-project run observed one transient `fetch failed` during a local fixture's event-stream connection, before the busy-session assertion ran. Thirty consecutive isolated runs of that entire OpenCode plugin test file passed. The cause of the transient transport failure was not established.

The final run of all `test-desktop/*.test.ts` recorded **1,042 passed, 0 failed, 0 cancelled and 45 skipped** in 251.6 seconds. It used the project network-isolation preload, one test file at a time, a 180-second file timeout, and Node's `--test-force-exit` option. An additional diagnostic preload rethrew fetch errors unchanged and recorded only loopback transport failures. It recorded no such failures in the final run.
